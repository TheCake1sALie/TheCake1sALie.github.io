# 完整实验博客：基于 Docker 容器的网络嗅探与报文伪造

## 实验环境
- 操作系统：Ubuntu 20.04 / 22.04
- Docker 20.10+
- Python 3.8+，Scapy 2.4+

---

## 一、环境搭建

### 1.1 创建项目目录并编写 Dockerfile

```bash
mkdir ~/docker_files && cd ~/docker_files
vim Dockerfile
```

**Dockerfile 完整内容**：

```dockerfile
# 基础镜像
FROM ubuntu:20.04

# 避免时区交互
ENV TZ=Asia/Shanghai
RUN ln -snf /usr/share/zoneinfo/$TZ /etc/localtime && echo $TZ > /etc/timezone

# 更换为阿里云镜像源（加速下载）
RUN sed -i 's/archive.ubuntu.com/mirrors.aliyun.com/g' /etc/apt/sources.list
RUN sed -i 's/security.ubuntu.com/mirrors.aliyun.com/g' /etc/apt/sources.list

# 安装基础依赖、网络工具、Python环境
RUN apt update && apt install -y \
    python3 \
    python3-pip \
    tcpdump \
    net-tools \
    iproute2 \
    iputils-ping \
    vim \
    wget \
    curl \
    git \
    && rm -rf /var/lib/apt/lists/*

# 配置 python/pip 软链接（强制覆盖）
RUN ln -sf /usr/bin/python3 /usr/bin/python \
    && ln -sf /usr/bin/pip3 /usr/bin/pip

# 安装 scapy（网络报文构造/解析库）
RUN pip install --upgrade pip && pip install scapy

# 开启无缓冲输出（便于调试）
ENV PYTHONUNBUFFERED=1
```

### 1.2 构建镜像

```bash
docker build -t netsec-env:v1 .
```

验证镜像：

```bash
docker images | grep netsec-env
```

### 1.3 创建自定义桥接网络

```bash
docker network create \
  --driver bridge \
  --subnet=192.168.60.0/24 \
  --gateway=192.168.60.1 \
  lab_net
```

### 1.4 创建三个容器

```bash
# hostA – 目标主机，IP 192.168.60.2
docker run -itd --name hostA \
  --network lab_net --ip 192.168.60.2 \
  --privileged netsec-env:v1

# hostB – 攻击者/嗅探者，使用宿主机网络（相当于物理机）
docker run -itd --name hostB \
  --privileged --net host netsec-env:v1

# hostM – 辅助主机，IP 192.168.60.3
docker run -itd --name hostM \
  --network lab_net --ip 192.168.60.3 \
  --privileged netsec-env:v1
```

### 1.5 验证网络连通性

```bash
docker exec hostA ping 192.168.60.1 -c 2   # 网关
docker exec hostA ping 192.168.60.3 -c 2   # hostM
```

应正常收到回包。

### 1.6 获取 lab_net 对应的网桥接口名

```bash
docker network inspect lab_net | grep -i "com.docker.network.bridge.name"
```

如果没有输出，可以通过以下命令查找（通常名为 `br-<网络ID前12位>`）：

```bash
ip link show type bridge
```

记下接口名，例如 `br-07b18cb1d1b8`，后续脚本中会用到。

## 二、实验一：TCP SYN Flood 嗅探

**实验目标**：hostA 向 hostB（宿主机）发送大量 TCP SYN 包，hostB 上的嗅探程序打印每个包的源IP、目的IP、源端口、目的端口、协议。

### 2.1 获取宿主机 IP（hostB 的 IP）

由于 hostB 使用 `--net host`，其 IP 即宿主机的 IP。在宿主机上执行：

```bash
hostname -I | awk '{print $1}'
```

假设得到 `192.168.1.100`（实际以你的为准）。

### 2.2 hostB 上的嗅探代码（`sniff_syn.py`）

进入 hostB 容器：

```bash
docker exec -it hostB /bin/bash
```

创建脚本：

```bash
cat > /sniff_syn.py << 'EOF'
#!/usr/bin/env python3
from scapy.all import *

HOSTA_IP = "192.168.60.2"
BRIDGE_IFACE = "br-07b18cb1d1b8"   # 请替换为实际的网桥名

def process(pkt):
    if TCP in pkt and pkt[IP].src == HOSTA_IP:
        print(f"源IP: {pkt[IP].src} | 目的IP: {pkt[IP].dst} | "
              f"源端口: {pkt[TCP].sport} | 目的端口: {pkt[TCP].dport} | 协议: TCP")

print(f"监听接口 {BRIDGE_IFACE}，等待来自 {HOSTA_IP} 的 TCP 包...")
sniff(iface=BRIDGE_IFACE, filter="tcp", prn=process, store=0)
EOF
```

**注意**：将 `BRIDGE_IFACE` 变量替换为你实际查到的网桥名。

### 2.3 运行嗅探程序

```bash
python3 /sniff_syn.py
```

程序会显示监听信息并保持运行。

### 2.4 hostA 发送 TCP SYN Flood

另开一个终端，进入 hostA：

```bash
docker exec -it hostA /bin/bash
```

使用 Scapy 发送 100 个 SYN 包到宿主机 IP（例如 `192.168.1.100`）：

```bash
python3 -c "from scapy.all import *; send(IP(dst='192.168.1.100')/TCP(sport=RandShort(), dport=80, flags='S'), count=100, verbose=False)"
```

### 2.5 观察结果

在 hostB 的终端中，应该会打印出类似以下的输出：

```
源IP: 192.168.60.2 | 目的IP: 192.168.1.100 | 源端口: 54321 | 目的端口: 80 | 协议: TCP
源IP: 192.168.60.2 | 目的IP: 192.168.1.100 | 源端口: 54322 | 目的端口: 80 | 协议: TCP
...
```

### 2.6 截图要求

1. hostB 中 `sniff_syn.py` 的内容（可用 `cat /sniff_syn.py` 展示）。
2. hostB 运行 `python3 /sniff_syn.py` 后的界面。
3. hostA 发送 SYN 包的命令及输出。
4. hostB 打印的多个包信息（至少 3 行）。

## 三、实验二：ICMP 请求伪造（Ping 欺骗）

**实验目标**：hostA ping 不存在的 IP `1.2.3.4`，正常情况下不通；hostB 运行伪造程序后，hostA 能收到回复。

### 3.1 原理简述

- hostA 的默认网关为 `192.168.60.1`，该网关实际是宿主机上的网桥接口。
- hostB 共享宿主机网络栈，可以监听该网桥接口上的 ICMP 请求。
- hostB 捕获来自 hostA、目标为 `1.2.3.4` 的 ICMP Echo Request，构造 Echo Reply 并从同一接口发回，hostA 即可收到。

### 3.2 hostB 上的伪造代码（`ping_fake.py`）

仍然在 hostB 容器内操作（如果已经退出，重新进入）：

```bash
docker exec -it hostB /bin/bash
```

创建脚本：

```bash
cat > /ping_fake.py << 'EOF'
#!/usr/bin/env python3
from scapy.all import *

HOSTA_IP = "192.168.60.2"
FAKE_IP = "1.2.3.4"
BRIDGE_IFACE = "br-07b18cb1d1b8"   # 请替换为实际的网桥名

def forge_reply(pkt):
    print(f"[*] 捕获请求: {pkt[IP].src} -> {pkt[IP].dst} id={pkt[ICMP].id} seq={pkt[ICMP].seq}")
    ip = IP(src=pkt[IP].dst, dst=pkt[IP].src)
    icmp = ICMP(type=0, code=0, id=pkt[ICMP].id, seq=pkt[ICMP].seq)
    payload = pkt[ICMP].payload
    reply = ip / icmp / payload
    send(reply, iface=BRIDGE_IFACE, verbose=False)
    print(f"[+] 伪造回复已发送")

print(f"监听接口 {BRIDGE_IFACE}，等待 {HOSTA_IP} -> {FAKE_IP} 的 ICMP 请求...")
sniff(iface=BRIDGE_IFACE,
      filter=f"icmp and src host {HOSTA_IP} and dst host {FAKE_IP}",
      prn=forge_reply, store=0)
EOF
```

**注意**：同样替换 `BRIDGE_IFACE` 为实际的网桥名。

### 3.3 运行伪造程序

```bash
python3 /ping_fake.py
```

程序会显示监听信息。

### 3.4 在 hostA 中测试 ping

打开一个新终端，进入 hostA：

```bash
docker exec -it hostA /bin/bash
```

发送 ping 到伪造的目标地址：

```bash
ping 1.2.3.4 -c 4
```

**预期输出**：

```
PING 1.2.3.4 (1.2.3.4) 56(84) bytes of data.
64 bytes from 1.2.3.4: icmp_seq=1 ttl=64 time=0.123 ms
64 bytes from 1.2.3.4: icmp_seq=2 ttl=64 time=0.098 ms
64 bytes from 1.2.3.4: icmp_seq=3 ttl=64 time=0.102 ms
64 bytes from 1.2.3.4: icmp_seq=4 ttl=64 time=0.115 ms

--- 1.2.3.4 ping statistics ---
4 packets transmitted, 4 received, 0% packet loss, time 3072ms
```

同时在 hostB 的终端会输出类似：

```
[*] 捕获请求: 192.168.60.2 -> 1.2.3.4 id=1234 seq=1
[+] 伪造回复已发送
[*] 捕获请求: 192.168.60.2 -> 1.2.3.4 id=1234 seq=2
[+] 伪造回复已发送
...
```

### 3.5 停止程序验证

在 hostB 终端按 `Ctrl+C` 停止脚本，再次在 hostA 中 ping `1.2.3.4`，应显示 100% packet loss。

### 3.6 截图要求

1. hostB 中 `ping_fake.py` 的内容（`cat /ping_fake.py`）。
2. hostB 运行 `python3 /ping_fake.py` 后的界面（包含捕获和伪造日志）。
3. hostA 中 ping 1.2.3.4 成功的完整输出。
4. （可选）停止程序后再次 ping 失败的对比截图。

## 四、常见问题与解决方案

| 问题现象 | 可能原因 | 解决方法 |
|----------|----------|----------|
| 容器间 ping 不通 | 网桥接口状态 DOWN | `sudo ip link set br-xxxx up` |
| tcpdump 抓不到包 | 接口名错误或未指定 | 使用 `-i any` 或正确的网桥名 |
| Scapy 发送失败 | 权限不足 | 容器需 `--privileged`，或使用 `sudo` |
| 伪造回复不生效 | 未复制原始 payload | 确保 `pkt[ICMP].payload` 被包含 |
| 实验一收不到 SYN | hostA 未正确获取宿主机 IP | 用 `hostname -I` 确认宿主机 IP 并作为目标 |
| Docker 命令需 sudo | 用户未加入 docker 组 | `sudo usermod -aG docker $USER` 并重新登录 |
